# mathengine — vendored sync

This directory is a vendored copy of the Math Engine (MEP) C11 sources from:

    https://github.com/Amit2286658/Math-Engine-MEP

## Precompiled Default Layout (`jniLibs/` + `assets/precompiled/`)

By default, `Ecalc` ships the **separated** exchange pair so startup requires **zero network calls** for the core engine or standard library, while the stdlib is **not duplicated** inside the binary:

* `app/src/main/jniLibs/arm64-v8a/libmathengine.so` — Math Engine (MEP) shared library (~283 KB, Android bionic, API 24, ARM64). The engine has **no embedded stdlib at all** — every engine boots blank; `nativeCreate()` and `nativeCreateBlank()` both return empty engines, and the host loads `stdlib.mathc` via `nativeLoadMathc()`. Host externs referenced by pulled `.math` patches (e.g. `@currency_convert`) degrade to a loud STRING result when no host callback is registered (`unavailable: host extern '@<name>' not implemented yet`) instead of failing the whole expression, and app-backed extern callbacks can be registered via `MathEngineBridge.nativeRegisterExtern` (with engine-side destructor cleanup on replace/destroy).
* `app/src/main/assets/precompiled/stdlib.mathc` — Precompiled 18-module `.mathc` standard library image (generated by `mathc` from `Library/*.math`), loaded at boot after blank-engine creation.

Rules of the pair:

1. **Same-snapshot invariant** — the `.so` and `stdlib.mathc` must always come from the same engine build. CI (`engine-artifacts`) enforces this by generating both from one source tree; `check_mathc.py` validates the image structurally (payload/checksum/caps) before upload.
2. There is only ONE engine mode now: blank boot + separately loaded `stdlib.mathc`. The `stdlib_precompiled.h` embedded-image header and the `MATH_ENGINE_SEPARATE_STDLIB` option were removed upstream (`Math-Engine-MEP`); `mathc` emits only the `.mathc` image (pass `-` as its header argument).
3. The Kotlin boot `nativeCreate()` fallback is retained as an ordinary blank-handle factory identical to `nativeCreateBlank()`; the app loads the bundled stdlib asset onto whichever handle it gets.

## Incremental `.math` Patches

New `.math` extension modules published after an app release are listed in `patches/manifest.json` in the repo:
* `MathPatchDownloader` checks `manifest.json` and downloads any missing `.math` files into `context.filesDir/math_patches/` without touching the running engine.
* `MathPatchLoader` scans `context.filesDir/math_patches/` and compiles/links any unloaded `.math` files into the active engine.
