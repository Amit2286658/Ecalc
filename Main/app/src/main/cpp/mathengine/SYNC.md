# mathengine — vendored sync

This directory is a vendored copy of the Math Engine (MEP) C11 sources from:

    https://github.com/Amit2286658/Math-Engine-MEP

## Unified Top-to-Bottom Executable Module Architecture

The vendored C11 engine uses a **single unified module execution model** (the legacy `Core/session/` layer has been completely removed):
- Every `.math` file or module (`[module_name]`) is directly executable top-to-bottom on its own (Python-style) with no entry point required, mixing type definitions (`$struct`), unit rules (`@dim`), functions, operators, constants, module-level variables (`:=` / `mut` / `const`), and top-level expressions.
- Multi-file projects link in topological order via `<[dep]` dependencies (`user_compile_unit` + `user_link_ext` or `nativeModuleEval`).
- Explicit **privacy, scoping, and mutability** rules apply to module declarations:
  - **Privacy (`pub` / `priv`)**: Declarations are public (`pub`) by default; prefixing a variable, constant, function/operator, or `$type` with `priv` restricts access to the declaring module while still allowing that module's public functions to use its private helpers and state.
  - **Scoping (3-Tier Lexical)**: Local `{ ... }` / parameter variables shadow current-module variables, which shadow imported public variables from active modules.
  - **Mutability (`:=` / `mut` vs `=` / `const`)**: `x := expr` or `mut x = expr` creates a mutable variable; `const c = expr` (or `c = expr` on a new module binding) creates an immutable constant that rejects reassignment and in-place container/struct mutation.
- JNI module entry points in `MathEngineBridge`:
  - `nativeModuleEval(handle, moduleName, expr)`
  - `nativeModuleReset(handle, moduleName)`
  - `nativeModuleFormatVars(handle, moduleName)`
  - `nativeModuleExportSource(handle, moduleName)`

## Precompiled Default Layout (`jniLibs/` + `assets/precompiled/`)

By default, `Ecalc` ships the **separated** exchange pair so startup requires **zero network calls** for the core engine or standard library, while the stdlib is **not duplicated** inside the binary:

* `app/src/main/jniLibs/arm64-v8a/libmathengine.so` — Math Engine (MEP) shared library (Android bionic, API 24, ARM64). The engine has **no embedded stdlib at all** — every engine boots blank; `nativeCreate()` and `nativeCreateBlank()` both return empty engines, and the host loads `stdlib.mathc` via `nativeLoadMathc()`. Host externs referenced by pulled `.math` patches (e.g. `@currency_convert`) degrade to a loud STRING result when no host callback is registered (`unavailable: host extern '@<name>' not implemented yet`) instead of failing the whole expression, and app-backed extern callbacks can be registered via `MathEngineBridge.nativeRegisterExtern` (with engine-side destructor cleanup on replace/destroy).
* `app/src/main/assets/precompiled/stdlib.mathc` — Precompiled 18-module `.mathc` standard library image (`244,361` bytes, generated by `mathc` from `Library/*.math`), loaded at boot after blank-engine creation.

Rules of the pair:

1. **Same-snapshot invariant** — the `.so` and `stdlib.mathc` must always come from the same engine build. CI (`engine-artifacts`) enforces this by generating both from one source tree; `check_mathc.py` validates the image structurally (payload/checksum/caps) before upload.
2. There is only ONE engine mode: blank boot + separately loaded `stdlib.mathc`. `mathc` emits only the `.mathc` image (pass `-` as its header argument).
3. The Kotlin boot `nativeCreate()` fallback is retained as an ordinary blank-handle factory identical to `nativeCreateBlank()`; the app loads the bundled stdlib asset onto whichever handle it gets.

## Incremental `.math` Patches

New `.math` extension modules published after an app release are listed in `patches/manifest.json` in the repo:
* `MathPatchDownloader` checks `manifest.json` and downloads any missing `.math` files into `context.filesDir/math_patches/` without touching the running engine.
* `MathPatchLoader` scans `context.filesDir/math_patches/` and compiles/links any unloaded `.math` files into the active engine.
